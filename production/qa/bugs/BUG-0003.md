- **Game State**: Immediately after acquiring PointerLock, before the first movement input

## Reproduction Steps
**Preconditions**: Load or refresh the prototype.

1. Click the initialization overlay to acquire PointerLock and reveal the HUD.
2. Do not press any movement key.
3. Read the coordinate display in the lower-left HUD.
4. Press `W` briefly and compare the updated coordinate display.

**Expected Result**: The initial HUD reads `0.0, 1.5, 0.0`, matching the camera position and configured `EYE_HEIGHT`.

**Actual Result**: The HUD initially reads `0.0, 0.0, 0.0`. It changes to a Y value of `1.5` only after the player moves.

## Technical Context
- **Likely affected files**: `index.html:17`, `src/main.js:21`, `src/main.js:66-76`
- **Related systems**: UI / HUD, FPS Movement position reporting
- **Possible root cause**: The HTML contains a hardcoded zero coordinate string, while the JavaScript updates the HUD only inside the non-zero movement branch.

## Evidence
- **Static evidence**: Camera Y is initialized to `EYE_HEIGHT` (`1.5`) at `src/main.js:21`; the visible HUD starts at zero in `index.html:17`; the first correction can occur only inside `if (dir.lengthSq() > 0)` at `src/main.js:66-76`.
- **Syntax check**: `node --check src/main.js` passed on 2026-06-27.
- **Runtime verification**: The live page loaded successfully on 2026-06-28 and the DOM reported `hud-coords` as `0.0, 0.0, 0.0`. Automated PointerLock acquisition was blocked by the browser's user-gesture requirement, but the code path remains deterministic.

## Related Issues
- `design/gdd/fps-movement.md:68`, `:322`, and `:329`
- `production/qa/bug-audit-handoff-2026-06-27.md`

## Notes
Recommended implementation direction: update the coordinate display from the camera position when PointerLock is acquired, or move position rendering into a shared function called at initialization and whenever position changes. Avoid duplicating gameplay coordinates as hardcoded HTML state.

## Fix Applied — 2026-06-30
**By**: Claude Code
- `src/main.js`: moved the clamp + `hudCoords.textContent` update out of the `if (dir.lengthSq() > 0)` branch so it runs every locked frame, not only on movement. The first locked frame now sets the HUD to the true camera position (`0.0, 1.5, 0.0`) regardless of whether the player has moved yet.
- `index.html` left unchanged — the `0.0, 0.0, 0.0` placeholder is now overwritten on the first locked frame.
- `node --check src/main.js` PASS. Vite dev server loads with no new console errors.
- **Not yet verified**: live DOM read of `hud-coords` immediately after a real PointerLock acquisition (sandboxed preview cannot acquire PointerLock). No automated test added — `tests/` directory does not exist yet.
