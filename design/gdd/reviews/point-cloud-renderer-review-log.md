**The model change.** Both densities now come from data the renderer already holds, instead of from config predictions:
- **`ρ_base` is measured, not predicted** — `N_base / A_tile`, the tile's own sealed BASE point count, maintained in the detection tile index at the moment Core Rule 7 seals points into BASE. It is no longer `D × W_s`. *User decision, offered against the CD's literal prescription (which kept `D × W_s` and added a binary owning-node completion gate): the measured baseline subsumes that gate — an unsealed tile has `N_base = 0` and is excluded — and additionally fixes the partially-sealed case, the room-edge/mixed-surface tile that legitimately holds fewer points than `D × W_s × A_tile`, and the auto-scaled-`D` staleness item, none of which the literal model closes. Same shape, more direct datum.*
- **`ρ_obs` is subsampled** — `(N_res × k/n) / A_tile` from `n = min(N_res, anomaly_tile_samples)` points taken on a systematic stride (never RNG, so the pass stays deterministic and unit-testable), default 128 per tile instead of every point.
- **The pass is swept across frames** — `anomaly_tiles_per_frame` (default 16) tiles per frame, completing the active set once per `anomaly_sample_interval`. Hard bound: **≤ `anomaly_tiles_per_frame × anomaly_tile_samples` points inspected in any single frame** (2,048 at defaults), asserted by AC-D11. *User decision: subsample **and** sweep, rather than subsample alone — the sweep is one knob and one AC, and it answers the engine-programmer's "no amortization Plan B" outright instead of leaving a ~3.5 ms lump justified by one unrepeated measurement on non-min-spec hardware.*
- **`N_min = ceil(1/k_noise²)`** (100 at defaults) — one derived constant replacing three separately-stated requirements: `min_coverage_fraction`, the unscanned-tile exclusion, and the four-round-open joint noise guard. It is also the runtime division-by-zero guard: a tile with `ρ_base = 0` is never sampled.
- **Deleted, not replaced:** `f_cov`, `ρ_base_eff`, `min_coverage_fraction`, and the derived worst-case points-per-pass arithmetic (which broke in two consecutive rounds; the ADR owns it now, with the prototype's measured 418 tiles / ~530k points as its input).

**Two defects found *by* the rebuild, fixed in it** (neither was on the round-7 list):
1. **The activity gate said "intersects the camera frustum."** It must be **fully inside**. A tile straddling the frustum edge has most of its points failing the frustum test for reasons unrelated to any entity, and read as a large false deficit on every sweep, at every screen edge, in every version since round 3. New AC-D12.
2. **`k_noise`'s stated rationale was false under a measured baseline.** It modelled Poisson variance between a tile's *expected* and *actual* count; with the baseline measured, that variance is already inside `ρ_base` and a normal tile now reads σ = 0 *exactly*. Restated as a sensitivity coefficient — the relative deviation equal to 1σ. Every threshold, worked example, AC and downstream consumer is numerically unchanged; only the justification moved. The `√(A_ref/A_tile)` term survives with its direction intact but its justification re-derived from sampling/quantization noise rather than Poisson counting.

**Incidental resolution:** the prototype's measured **87 ms tile-index build** vs AC-E04's same-frame BASE rebuild is dissolved by making the index explicitly **incremental and never same-frame-required** — a tile whose bin is not built is simply not active. AC-E04's own text is untouched (track 3).

Document changes: Formula 2 replaced in full; Formula 1b's `ρ_base_local` decoupled from Formula 2's `ρ_base` (it is the *nominal* `D × W_s`, used to size geometry) and its worked example renumbered against a measured 1,080 baseline; Tuning Knobs — `min_coverage_fraction` deleted, `anomaly_tile_samples` (128, 64–512) and `anomaly_tiles_per_frame` (16, 4–64) added, the broken 1.77M/636k arithmetic stripped from the `A_tile` and `anomaly_sample_radius` notes (**the round-6 range narrowings themselves were left in place — they are no longer load-bearing under a per-frame bound, but un-narrowing them is a tuning decision this session did not take**), `k_noise` relabelled, interaction notes rewritten; AC-D02, AC-D02b, AC-D06 rewritten in place; AC-D09 (sample-size load guard), AC-D10 (estimator determinism + accuracy), AC-D11 (per-frame bound + sweep completeness), AC-D12 (frustum-straddling tile excluded) added. **AC count 33 → 37.**

### Addendum — 2026-07-26, post-review: Formula 5 pins a shader chunk that does not exist in r171 (BLOCKING, +1 → 9 blockers)
Found **after** the round-7 verdict was recorded, while building the Open Q#7 prototype — by verification
against the **installed `three@0.171.0` source**, not by any specialist reading the doc. This is the first
finding in seven rounds produced by checking the pinned engine rather than by argument, which is itself
evidence for the "go prototype" decision.

**Defect.** Formula 5's normative fragment-injection pin reads: *"applied to `outgoingLight` … inside the
`#include <output_fragment>` block, strictly before `#include <tonemapping_fragment>` and
`#include <colorspace_fragment>`."* **`output_fragment` does not exist in r171** — it was renamed
`opaque_fragment` in r152. Verified two ways: `node_modules/three/src/renderers/shaders/ShaderChunk/`
contains `opaque_fragment.glsl.js` and no `output_fragment.glsl.js`; and `ShaderLib/points.glsl.js`'s
fragment body reads:
```glsl
outgoingLight = diffuseColor.rgb;
#include <opaque_fragment>      // gl_FragColor = vec4( outgoingLight, diffuseColor.a )
#include <tonemapping_fragment>
#include <colorspace_fragment>
```
**Failure mode.** An implementer following the GDD literally writes
`shader.fragmentShader.replace("#include <output_fragment>", …)` — a string that never matches. The
replace **silently no-ops**, the flicker never renders, and **AC-D08 still passes**, because AC-D08
asserts only the CPU-side `uFlickerAmp` uniform and the unchanged base-colour uniform — never that the
injection took effect on the GPU. Same invisible-failure class the GDD explicitly worries about in its
own Layer-stack Transparency note ("their horror read would fail silently while a material-flag
assertion still passed").

**What survives.** The GDD's *reasoning* is confirmed correct against the real shader: `opaque_fragment`
does precede `tonemapping_fragment` and `colorspace_fragment`, so the pre-tonemap requirement and the
linear `m ∈ [0.4, 1.0]` range are sound. Only the chunk **name** is wrong. Also confirms
engine-programmer's round-7 minor note — `outgoingLight` is assigned *before* the chunk expands, not
"inside" it — as literally accurate rather than cosmetic.

**Fix when the Formula 5 work happens (do NOT patch in isolation, per the standing ruling):** rename the
pin to `opaque_fragment`; state the r152 rename so a future revision bump re-checks it; and widen AC-D08
with a clause asserting the injection actually landed (e.g. the compiled `fragmentShader` source contains
the injected multiply, or a WebGL-integration-tier readback shows BASE pixel brightness changing between
`uFlickerAmp` 0 and 0.4) — an assertion on the uniform alone provably cannot catch this.

**Process note.** Related to but distinct from round-7 blocker 4 (`toneMapped=false` asymmetry). Both live
in Formula 5's round-6 injection-point fix; together they mean that fix introduced two defects, raising
round-6's self-inflicted count from 5 to 6 of 9. Reinforces CD's core diagnosis and the round-8 exit
criteria unchanged.
